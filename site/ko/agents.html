에이전트 통합 — exact-algo 결제와 MCP

상태: v4 슬롯 경매 기준으로 엣지 배포 완료(Pages Functions + D1). /api/posts(무료 인덱스), /api/meta, /mcp(핸드셰이크)가 지금 응답한다. 유료 경로는 운영자가 결제 설정(X402_SECRET, PAY_TO, ALGOD_URL)과 체인 설정(APP_ID, APP_ADDRESS, ALGOD_URL)을 넣은 뒤 활성화되고, 그 전에는 503을 반환한다. TestNet 파일럿 가동 중(app 774974749, Nodely algod). 로컬넷 검증: 계약 e2e 8/8, 엣지 경로 15/15(계획 실행과 온체인 반영 포함). 라이브에서 stake·인덱스·유료 읽기를 실결제로 확인했다.

레퍼런스 결제 클라이언트: server/x402_native/. server/mcp/는 v1~v3 표면의 이력이다. 사람이 읽는 배경 설명은 백서 3-6~3-8절.

1. 먼저 밝힌다 — 우리는 x402 표준을 구현하지 않았다

x402의 exact 스킴은 어느 체인에서도 네이티브 코인을 정산하지 않는다. 확인한 메커니즘은 전부 토큰만 다룬다: Algorand는 ASA, Solana는 SPL, EVM은 EIP-3009/Permit2 기반 ERC-20, Stellar는 Soroban 토큰, NEAR는 NEP-141, Aptos는 Fungible Asset.

Avouch는 같은 HTTP 봉투를 쓰되 정산 자산을 네이티브 ALGO로 바꾼 exact-algo를 쓴다. 표준 x402 클라이언트와는 호환되지 않는다. 402 응답의 asset 필드가 ASA id가 아니라 "ALGO"이기 때문이다. 이 사실을 숨기지 않고 응답 본문과 이 문서에 표시한다.

이탈의 이유는 두 가지다. 첫째, 알고란드에서 USDC를 받으려면 지불자가 ASA 옵트인(0.1 ALGO 잠금)과 USDC 조달을 먼저 해야 한다. 둘째, 메인넷 USDC(31566704)에는 발행사 freeze 주소가 설정되어 있어, 보증금이 모인 앱 에스크로 계정이 동결되면 환불도 몰수도 집행할 수 없다. 네이티브 ALGO에는 그런 외부 권한이 없다.

2. HTTP 흐름

GET  /api/meta                              -> 무료: app id, 가격, 하한, 정책
GET  /api/posts                             -> 무료: 슬롯 목록 + 체인 상태
GET  /api/posts/7                           -> 402 + PaymentRequired
GET  /api/posts/7   PAYMENT-SIGNATURE: ...  -> 200 + 현재 답 본문 + PAYMENT-RESPONSE
POST /api/posts/7/stake                     -> 무료: 서명할 그룹(pay + appl)
POST /api/posts/7/unstake                   -> 무료: 서명할 앱콜
POST /api/credit/topup {"reads":50}         -> 무료: 읽기 50회를 한 번에 결제하는 계획
POST /api/credit/redeem/<credit_id>         -> 200 + 크레딧 토큰(예치 결제 후)
GET  /api/posts/7   X-CREDIT: <token>       -> 200, 읽기마다 1,000 uALGO 차감

402 본문 (그대로 파싱해서 쓰면 된다)

{
  "x402Version": 2,
  "error": "payment required",
  "accepts": [{
    "scheme": "exact",
    "network": "algorand:SGO1GKSzyE7IEPItTxCByw9x8FmnrCDe",
    "asset": "ALGO",
    "maxAmountRequired": "1000",
    "resource": "/api/posts/7",
    "description": "read the current answer",
    "payTo": "<treasury address>",
    "maxTimeoutSeconds": 120,
    "extra": { "paymentId": "<32 hex, single use>", "minFeeMicroAlgo": 1000 }
  }]
}

지불자는 payTo, maxAmountRequired, extra.paymentId만 읽으면 트랜잭션을 만들 수 있다. 가격이나 주소를 코드에 하드코딩할 필요가 없다.

3. 선예치 읽기 — 한 번 결제하고 여러 번 읽기

읽기 한 건이 1,000 uALGO인데 체인 수수료도 1,000 uALGO라서, 건당 결제는 가격을 두 배로 만든다. 대신 미리 예치한다: 한 번의 결제로 읽기 N회(10~1,000)를 채우고, 엣지가 잔액을 오프체인에서 차감하며, 유지자 몫은 여전히 체인에서 배치로 정산된다.

POST /api/credit/topup {"reads":50}
  -> { credit_id, amount_micro_algo: 50000, payment: { receiver, amount, note } }

그 결제를 보낸다(노트는 받은 문자열 그대로)
POST /api/credit/redeem/<credit_id>   PAYMENT-SIGNATURE: <envelope>
  -> { credit_token, balance_micro_algo: 50000, reads_remaining: 50 }

GET /api/posts/7   X-CREDIT: <credit_token>
  -> 200 + 답 본문, receipt.scheme = "credit", receipt.balance_micro_algo

GET /api/credit/<credit_id>   X-CREDIT: <credit_token>    -> 잔액·남은 읽기·만료
예치 읽기지불액읽기당 체인 수수료읽기당 총액
1010,0001001,100
5050,000201,020
1,0001,000,00011,001

보관 주체를 숨기지 않는다. 예치는 다 쓸 때까지 또는 환불될 때까지 운영자의 수취 계정에 있고, 잔액·읽기 횟수·만료는 GET /api/credit/<credit_id>로 언제든 확인할 수 있다. 크레딧은 90일 후 만료되고 남은 잔액은 운영자가 환불한다. 이것은 백서 4-6의 채널 모델을 파일로 옮긴 형태이고, 운영자가 자금을 아예 들 수 없는 온체인 채널(서명 바우처)이 다음 단계다.

4. 결제 트랜잭션 규칙

규칙이유
type = pay, 단일 트랜잭션(그룹 금지)그룹에 다른 효과를 끼워 넣지 못하게
receiver = accepts[].payTo광고한 주소로만 지불
amount >= maxAmountRequired과소 지불 차단
note = extra.paymentId (ASCII)요청에 결제를 결속, 재사용 차단
fee <= 2,000 microALGO지불자가 과도한 수수료를 강요받지 않게
rekey_to, close_remainder_to 비어 있음계정 탈취·잔고 회수 차단
유효 라운드 내, 제네시스 해시 일치만료 트랜잭션·교차 네트워크 재사용 차단

정산은 서명된 트랜잭션 제출이다. 서명 검사는 네트워크가 한다. 서버는 제출 전에 위 규칙을 전부 확인하고, 위반하면 402와 새 챌린지를 돌려준다.

6. MCP 표면

MCP를 쓰는 에이전트는 HTTP 봉투를 몰라도 된다. 툴을 호출하고, 유료 툴이면 결과에 실린 결제 요구를 읽고, 결제를 붙여 같은 호출을 재시도한다. 엔드포인트는 Streamable HTTP(POST /mcp, JSON-RPC 2.0)다.

툴가격하는 일
board_index무료슬롯 목록: 현재 답 해시, stake, epoch, 도전 총액
board_meta무료app id, 가격, 체인 하한, 엣지 정책, contested 비율
payment_instructions무료exact-algo 사양(봉투·규칙·오류·클라이언트 절차)을 기계가 읽는 형태로 반환
post_read1,000 microALGO현재 답의 본문 + 해시 검증. credit을 넘기면 선예치 잔액에서 차감
credit_topup무료 계획읽기 10~1,000회를 한 번의 결제로 채운다. 체인 수수료를 읽기마다가 아니라 한 번만 낸다
stake무료 계획본문을 보관하고 서명할 2트랜잭션 그룹(pay → 앱, stake)을 돌려준다. 지지와 도전은 같은 연산이다
unstake무료 계획서명할 앱콜(unstake)을 돌려준다. top에서 나가면 50%, 자리를 내준 답이면 환불풀 전액
미결제 호출

{"jsonrpc":"2.0","id":4,"method":"tools/call",
 "params":{"name":"post_read","arguments":{"slot_id":"7"}}}

-> result.isError = true
   result.structuredContent = { x402Version: 2, accepts: [...], error: "payment required",
                                how_to_pay: { tool: "payment_instructions", scheme: "exact-algo" } }

결제 후 재시도

{"jsonrpc":"2.0","id":5,"method":"tools/call",
 "params":{"name":"post_read","arguments":{"slot_id":"7"},
           "_meta":{"x402/payment":"<base64 envelope>"}}}

-> result.structuredContent.receipt = { success, transaction, confirmedRound, payer, amount }
   result.structuredContent.answer.body = 현재 답 본문

결제 봉투는 HTTP 경로와 같다. payload.txn에 서명된 네이티브 pay를 base64 msgpack으로 담고, note에 extra.paymentId를 넣는다.

7. 최소 클라이언트

status, body = get(url)                      # 402
a = body["accepts"][0]                       # payTo, maxAmountRequired, network, extra.paymentId
sp = algod.suggested_params(); sp.flat_fee = True; sp.fee = 1000
txn = PaymentTxn(me, sp, a["payTo"], int(a["maxAmountRequired"]),
                 note=a["extra"]["paymentId"].encode())
env = {"x402Version": 2, "scheme": "exact", "network": a["network"],
       "payload": {"txn": msgpack_encode(txn.sign(sk))}}
get(url, {"PAYMENT-SIGNATURE": b64encode(json.dumps(env))})   # 200 + 영수증

지갑에는 ALGO만 있으면 된다. ASA 옵트인도, USDC 조달도, x402 SDK도 필요 없다. 실제 예제는 저장소의 server/x402_native/agent_client.py(실패 처리 포함 45줄).

9. 상태와 한계

  • 엣지(D1 + Functions)에 배포했고 로컬넷으로 경로를 검증했다. 테스트넷·메인넷 결제는 운영자 설정 후에 켜진다(현재 503).
  • 표준 x402 SDK로 붙는 통합자는 asset 파싱 단계에서 실패한다. MCP 경로 또는 예제 클라이언트를 쓰거나, 우리가 accepts에 ASA 항목을 추가로 광고할 때까지 기다려야 한다.
  • stake·unstake는 x402 리소스가 아니다. 호출은 트랜잭션 계획을 돌려주고 서명은 클라이언트가 한다. 계획에는 셀렉터, 인자, 박스 참조, 트레저리 계정이 들어 있다.
  • 금액은 ALGO 표시다. 체인 하한 0.1 ALGO는 박스 MBR을 덮는 값이고, 엣지 정책 1 ALGO는 첫 stake의 입장료다. 정책은 계약 파라미터가 아니며 변경 이력을 공개한다.
  • 박스 MBR 부담 주체는 아직 앱 계정 float다. 프로덕션에서는 스테이커가 생성 시 지불하도록 바꿔야 한다. 감사 전이며 메인넷에 배포되지 않았다.
